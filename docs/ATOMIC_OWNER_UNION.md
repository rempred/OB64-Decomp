# Atomic original-owner union

`atomicText: { schemaVersion: 1, mode: "atomic-contiguous-owner-union", alignment: 4 }`
is an explicit linkage admission for one original logical function archived across
two or more complete physical text rows. It retains one executable input section,
one output section and its load mapping, including the original serialized text
relocation stream. The accepted physical rows remain unchanged and are verified
as intervals within that contribution. This is a distinct representation; existing
multi-owner splitting and compilation-group modes retain their restrictions.

The original logical-function registry must independently authenticate exactly one
complete body covering the union, including its ROM hash and every whole original
row fragment. The registry's private authentication token and original row identity
are required. Compiler function size, assembly comments, copied registry objects,
preserved production envelopes and unrelated adjacent bodies cannot supply this
authority. Padding and unavailable logical-body overlap reject. Registration of an
inactive original body does not activate C or establish a match.

The compiler must emit exactly one GLOBAL function covering the entire union.
There is no text-tail contract, including a zero-length tail. The supported section
assignment uses alignment four, preserving every executable byte and the complete
text relocation section. Actual input and output alignment, start, size, map
contribution and load mapping must agree without prepadding. This permits original
functions whose complete size or placement is not a multiple of sixteen. All
physical members must be selected together; partial activation, overlapping
producers, duplicate outputs and either original fallback contribution reject.

Continuation owner names survive as GLOBAL, zero-size, non-function boundary
markers at their original addresses. They are not additional functions. The input
reference census permits unchanged zero-addend address references (R_MIPS_32 or
complete HI16/LO16 address pairs), rejects direct callable entries and unsupported
addends, and rejects duplicate providers. Producer relocations cannot use these
markers as alternative entry points. This does not infer a callable ABI from a
physical row boundary.

The mode requires fixed-row auxiliary projection schema 4. Each payload segment
owns exactly one complete original read-only row and lists its authentic compiler
`occurrences`, each with `label`, section-relative `offset`, `bytes` and ordered
`alignmentDirectives`. Multiple adjacent compiler tables can occupy one row; their
entry bytes must cover that row's declared entries exactly. The row's trailing
zeros, including the last row's zeros, must be the minimal actual native alignment
bytes established by emitted directives and the object's section alignment. They
are copied from the compiler object, never synthesized. Existing schema meanings
are unchanged, including schema 2's owned-terminal-padding rejection.

Every table entry has one original R_MIPS_32 relocation, aligned and directed
inside the complete function. Destinations may cross physical row intervals.
Section anchors, encoded addends and text/table relocations are conserved through
the existing auxiliary projection. Writable, unexplained executable, COMMON,
extra function or allocated data contributions reject.

Text-contract schema 7 records both the actual contribution and complete physical
intervals, original logical binding and boundary markers. Object-evidence schema
11 and nested auxiliary schema 4 retain raw, projected and stripped section,
symbol and relocation censuses; link evidence includes the complete linked census
and each physical interval's bytes. Strict proof validation rereads the registered
on-disk artifacts and ELF/map and independently reconstructs the entire proof.
Comparing a forged report with itself cannot establish authority. Cache restoration
repeats artifact/source-policy checks and projection, with implementation and
logical-registry identities in its authenticated inputs.

Accounting retains physical-owner counts but counts one logical function and its
text bytes once. Original row layout remains the reference model; the link view
uses the authenticated union contribution. Public scratch commands do not admit
this representation or compilation groups. This is not a new private group CLI.

`tests/atomic_owner_union.js` compiles an independent PURE_C producer at two
placements with signed-low carry controls, a real HI16/LO16 pair across the
physical cut, multiple tables per original row, terminal zeros and a nonmultiple16
function. It checks linked boundary-address preservation, physical-byte and
asm-differ comparisons, source-policy proof, cold/warm cache and malformed,
self-compared and stale controls. A changed source must stay nonexact. Generated
artifacts stay in `build/tests`. Structural acceptance additionally requires
independent review and one changed-input audit; no unfinished source wave is
accepted by this capability.

The optional `node tests/atomic_owner_union_real.js` requires the preserved W8
source pair and the separate original-body review under `build/audit`. It binds
that reviewed body privately without modifying the registry. The complete EBBC
candidate and genuine no-step-loop control are both compiled and linked through
the new representation; the control retains its 33 differing instruction words.
These source-bound diagnostics are separate from the registered independent test
and from production matching acceptance.
