# Workflow B — parallel candidate matching

Use this pilot when a worker understands what a function does and can name two plausible C changes that the pinned compiler could distinguish. Each source worker owns one current function and two exclusive private comparison directories. One worker can test two variants concurrently. With three enrolled workers, the Director can allocate up to six concurrent checks across their three functions. The existing integrator still owns the canonical build. [Test recipe and results](workflow-b-test.md) · [Canonical private-workbench contract](../WORKFLOW.md#private-candidate-workers)

Connor described one agent using m2c, a permuter and parallel compiles, and reusing a finding on a parked function. B tests two parts of that account separately: the time saved by trying independent alternatives together and the value of a source change on another worker's function. The first version uses the project's pinned compiler and ordinary, readable C variants. A worker can write the alternatives or generate a small explicit list from its own source. The pilot can run today without installing a permuter.

## Run with one source worker

Give the incoming worker its full function roster, the exact selected inputs, two exclusive writable roots and read-only access to its predecessors’ saved sources, reports and compiler observations. Start from a preserved parent and keep its useful competing controls. On a source move, check that the compiler sees the intended source and headers. Copy only the inputs needed for a candidate; leave the original snapshots, databases and reports in place.

For one current target, predict what each of two independent changes should alter and what should stay exact. Run one variant in each root, compare the complete results with the same parent, and keep the best reproducible source in the primary root. A register or delay-slot improvement can be useful even if the old best remains ahead overall. Carry that evidence into the next relevant function. Keep already-exact candidates for the complete wave. A production assignment can use this loop directly; the timed comparison in the test guide is optional.

## Set up a trial

1. **Director:** choose three eligible cases in existing authorized waves. Record the worker, target and any coupled rows, private input-set ID, launcher, slots and total job budget in the existing assignment or cursor. Resolve overlap with other workers and contributors. Preserve existing active assignments unless explicitly enrolling them. A replay of retained sources belongs in fresh roots.
2. **Integrator:** supply the verified release and complete-wave preflight using the normal workflow. One selected v2 manifest and its exact bundled launcher can serve multiple slots. Coordinate drains before referenced tools, inputs or accepted outputs change. Allow room for the canonical writer and other workloads.
3. **Workers:** use the normal intake, caller evidence, disassembly and any available independently derived m2c draft to establish what the function must do. Read the required-body, ABI, relocation and table contracts. The private selected-input commands support authored candidates; use the documented preparation path if a new decompiler draft is needed. Check the first meaningful difference before designing variants. [Workbench commands](../MATCHING_WORKBENCH.md) · [Worked examples](../research/how-matching-works-20261117.md)

| Example assignment | Worker’s two exclusive directories under `build/matching/` | Maximum native commands |
| --- | --- | ---: |
| Worker 1, target A | `wb-a1`, `wb-a2` | 2 |
| Worker 2, target B | `wb-b1`, `wb-b2` | 2 |

The names are examples. Each directory is an immediate sibling under `build/matching/`, with its own guarded process, database and artifacts. Keep one primary cursor and one best source per worker. Use six as a **trial ceiling**, inclusive of each worker’s primary checks, not a 16-core entitlement. If only four slots are available, allocate 2/1/1 and rotate the spare between batches. A probe consumes a slot too. Each owner waits for its slot to finish before issuing another command there. On contention, finish the current batch and lower the next batch width. ## One batch on one function

1. **Freeze the starting candidate.** Give it a stable source path and retain the completed report. Note the evidence mode, first differing instruction or relocation, correct body extent and any calls, table entries or code regions already exact. If the difference is an unresolved symbol, wrong prototype, missing side effect or wrong target extent, investigate that first.
2. **Write a question with competing answers.** For example, “Does this branch delay slot change when two predicates share an assignment, or when the flag is initialized earlier?” Make both variants from the same parent. Change one idea per file, preserve C evaluation order and side effects, and predict both a local effect and a whole-function invariant. Keep the original candidate as the control. Duplicate sources or candidates producing the same instructions give one outcome.
3. **Compile independently.** Place each complete source inside its assigned slot and run the selected launcher's `watch <symbol> --source <slot/file.c> --inputs <manifest> --scratch-root <slot> --native-concurrency parallel --json`. Use the runnable PowerShell example in the test recipe. Both commands must use the same target, manifest, launcher and meaningful include context. Store the full reports. A returned `busy` means the slot already has a command; wait. On shared-input drift, drain the affected slots and follow the normal release path.
4. **Inspect before combining.** Compare each output against the parent and retail. Check the intended instruction change, gains **and losses** across the entire function, frame size, calls, relocation operands and owned data. A score can improve by moving a mismatch elsewhere. Raw object bytes, relocation-masked bytes and isolated linked diagnostics answer different questions. Check candidate IDs and cache status when counting builds. Where an unresolved operand prevents an exact comparison, record it as unresolved.
5. **Choose the next action.** Preserve a whole-function improvement with its report. If two changes help different regions, test their combination as a fresh candidate. If two variants generate identical code, or two small batches leave the same unexplained difference, inspect the relevant compiler pass or caller and choose a different experiment. Keep a locally useful but globally regressive variant as a counterexample. On a private exact result, recheck the retained source from the primary slot if the path or include context changed; hand off the complete wave under the ordinary rules.

For a larger search, enumerate a finite list of defined, source-policy-compliant alternatives in the worker's private space, then feed the list through the same two occupied slots in batches. Examples include pointer versus indexed access to the same object, a common flag assignment, or the lifetime of a temporary. Save the generator settings or seed, parent and winning source. Use the same job and elapsed-time budget. An external decomp-permuter backend would need its own pinned-compiler compatibility test and attribution of search cost before its results could be compared. Never fold changes in required reads, volatile accesses, signed overflow behavior or ABI into a scheduling experiment.

## Make a fix available to the other two workers

**Donor.** When an experiment changes the next decision another worker could make, put one compact entry in the existing private cursor or research observation. Keep a resolvable source pair and report. Include the symptom, what was already correct, the one C change, the actual local and whole-function effect, a case where it failed if known, the input set and a condition that makes the idea inapplicable. A partial fix can be worth sharing.

**Director and integrator.** At pilot setup, give all three workers read-only links to the three designated lesson sections in their existing cursors. Each owner writes only its own entry. This gives workers a route to same-session discoveries between batches. Keep links to closed source/report pairs; leave mutable databases private. The integrator publishes durable observations through the existing research path, and the Director indexes reusable lessons. A captured input manifest contains historical research; a later lesson needs an explicit pointer or a later selected release. [Research intake and publication](../WORKFLOW.md)

**Recipient.** When the current symptom changes, a batch stalls, or a parked target resumes, check relevant new entries and existing intake. With the selected launcher, use `intake <symbol> --inputs <manifest> --scratch-root <primary>` and, where supported by that release, `--symptom register-allocation` or `--cross-limit 3`. Check whether the donor’s preconditions hold. Apply the smallest analogous edit to your own source alongside your current control. Record the donor link and the measured recipient outcome in your own cursor. If a parked target belongs to the other worker, leave the lead for its owner; keep the one-current-target rule.

**Example entry:** “Display, decimal parser. Two registers are now correct, but initializing the flag earlier displaced a literal from a branch delay slot. One short-circuit test with a common assignment restored both positions; the frame and 611-word extent held. Look for duplicate flag-setting paths with the same evaluation order. An unresolved call operand is a different symptom.” [Donor source controls](../../build/matching/army-display/55B28-reconstruction.md)

## Start and finish

The Director can append this brief to each existing worker assignment:

> Run Workflow B on **[target and complete-wave obligation]** with **[selected release]** in **[two exclusive slots]**, within **[job cap and time window]**. Start at **[parent source/report and first mismatch]**. Keep **[known-correct region, calls or table]** intact. Read **[three lesson sections]** at the next relevant decision. Retain one best candidate and report what happened to each hypothesis. Send the usual complete-wave handoff or actionable blocker through the existing Director route.

The integrator reconciles interfaces and source ownership and performs canonical linking, relocation checks and the full US Rev 0 ROM comparison. A privately exact result is recorded separately until the complete wave passes. At the trial boundary, record timings, blocked cases and actual cross-worker transfers using the test recipe. Drain trial slots before reassigning them and retain source/report pairs still referenced by lessons. Ordinary matching can resume with one slot per worker at the next batch boundary.
