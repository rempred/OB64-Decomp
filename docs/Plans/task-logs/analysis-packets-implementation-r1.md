## Cache and failure behavior

Cache identity binds the complete retail ROM hash, selected owner/mapping, supplied metadata, code/assembly, tool configuration, adapter/readers, Node and environment digest.
Before reuse, the command reauthenticates those inputs and checks the artifact census, file hashes, packet identity and imported Python dependency hashes.
Python runs in isolated mode without bytecode writes. Its imported-file evidence supplements executable and complete m2c-tree pins.
This is a trusted local cache with drift detection, not a signed archive resistant to an attacker rewriting every artifact.
It also does not certify an entire operating system or dynamic-library dependency closure.

Tool executable/spec/script drift prevents that tool's execution while the other tool may still produce a visible result.
Timeouts and missing tools remain partial packets. No tool failure affects ordinary compilation, linking or verification commands.
Exclusive packet-directory creation prevents concurrent packet writers. Interrupted or corrupt caches reject; `--fresh` preserves them and produces a separate directory.
The tool never deletes prior evidence or automatically compiles/adopts generated C.
