## Bounded packet policy

- At analysis intake for a large/difficult function, generate raw m2c and Kuna default output once from the same authenticated owner/mapping, then cache by input/tool/options identities. Keep the outputs separate from canonical source.
- Include statuses, timing, tool versions, supplied metadata/types/tables and known limitations. Missing tables and processor failures must remain visible; do not silently substitute a different interpretation.
- Compare consequential disagreements at the instruction/value level. Inferred prototypes, array capacities and merged variables remain hypotheses. Do not require an additional ordinary matching-review gate.
- Request alternate transformations only for a specific observed ambiguity. This trial's collapse mode produced no new output, and the explicit MIPS64/O32 configuration failed larger samples; running every option by default is unsupported.
- Keep packet generation out of compilation, linking and canonical verification. Do not automatically compile/adopt output or create a dependency on either analysis tool for the normal build. A future shared packet generator is separate implementation work with its applicable tooling review; it was not authorized or implemented here.
