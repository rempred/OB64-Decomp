## Lifecycle and evidence limits

Explicit runtime mode first authenticates source/runtime files and requires all critical native checks to PASS, not SKIP. It verifies the selected knowledge database through read-only APIs and refuses a different explicit path, database ID or frontier. It checks the configured input file hash and the ROM. It does not select, initialize, repair or ingest knowledge.

Live preflight must report the assigned port/epoch, exact ROM, interpreter core, empty queue and no existing instrumentation. No session recovery, process launch or foreign-session shutdown occurs. A fresh run directory is created only after these prerequisites. Normal recorder startup then rechecks live preflight against the staged session metadata. The adapter does not register itself as the global latest session or overwrite another worker's session record.

The observation loop stops after draining a signature-qualified entry or reaching the approved 1..300-second budget. The entry is only a stopping trigger. Batching can retain more than one invocation; immediate shutdown can also leave incomplete invocation state. Startup, individual bounded requests, draining and final verification mean the budget is not a hard process-termination deadline. The accepted final drain preserves explicit sequence/epoch/loss checks. Ctrl+C or an exception produces interrupted evidence, not a successful observation.

The normal raw-session manifest and verifier run after closure. A failed verification or interruption remains explicit. The adapter never ingests and always reports live-unreviewed. Output contains the raw staging database, approval/configuration/readiness records, manifest and adapter-result.json. No duplicate NDJSON stream is created.

entry_seen does not prove a caller or pointer origin. Acceptance requires connected actual callsite/delay-slot/target or incoming-edge evidence, contemporaneous placement, entry arguments and target-definition/load state. Generic hits at a reused overlay address are unqualified. A tail jump needs its actual incoming edge; RA alone is insufficient. An interior entry is a raw lead requiring its exact register-state interpretation.

If the first observation omits the target's last definition, the result remains partial. Inspect the captured caller and prepare a narrower separately approved follow-up. No broad whole-program register trace or inferred origin is substituted. A bounded miss does not prove dead code.

The pre-return focused packet precedes the result-producing delay slot. It must not be presented as returned v0. Addressed byte, post-delay return value and first-result-use evidence are optional additional inputs for a behavioral name. The adapter explicitly withholds that claim and makes no automatic semantic promotion.
