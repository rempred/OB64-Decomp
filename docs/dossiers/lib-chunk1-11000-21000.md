# Chunk 1 Library Split — `0x00011000..0x00021000`

Source-layout split of the second 64 KiB code chunk (RAM `0x80080C00..0x80090C00`,
simple mapping `RAM = ROM + 0x8006FC00`). **350 tracked files** under
`asm/original/rev0/lib/` (chunk 1 is fully split; chunk 0 stays in
`asm/original/rev0/boot/`). Byte-exact rebuild preserved (code SHA
`40D4E787…B409`, ROM SHA `571E8339…CC67A`).

This is **not boot code** — it is a mixed runtime library reached from gameplay
states (callers in `0xFFxxx`, `0x29Dxxx`, `0x2B7xxx`, …): a unit/character record
subsystem, a tagged command/script interpreter, float math (trig/sqrt/ldexp),
libc (`memset`/`memmove`/byte-copy), allocators / free-lists, glyph⇄ASCII text
encoding, and libultra OS primitives (cache ops, AI audio, CPU interrupt mask,
virtual→physical). Hence the `lib/` directory rather than `boot/`.

## Method

- Seeded from `tools/dump_function_context.js --start 0x11000 --end 0x21000`
  (277 parent records; exclusive ends = `end_rom + 4`).
- Built a deterministic base partition (252 files: cut at primary function starts,
  drop overlap-secondary entries, force the straddler-tail boundary `0x11168`).
- Ran a 9-slice swarm (analyze → adversarial review per slice). Reviewers
  **un-merged** functions the parent DB lumped, **folded** read-before-write
  preamble-orphans forward, kept genuine dual-entries as one file, and demanded
  hard evidence for every descriptive name (default `func_XXXXXXXX`).
- Net result **350 files** (more granular than the 277 parent records): the
  parent DB had hidden many tiny jal-reachable accessor/leaf functions inside the
  trailing bytes of larger records (see Boundary corrections).
- Every boundary re-verified word-by-word against the disasm (each start a real
  `addiu $sp,-N` prologue or proven jal-only leaf / preamble true-entry; each end
  a `jr $ra` + delay slot). `node tools/verify_setup.js` PASS confirms byte-exact.

## Subsystem map (address clusters)

- `0x11000..0x11168` — `euler_to_matrix_full_tail`: the tail of the chunk-0
  straddler `euler_to_matrix_full` (`0x10FE0..0x11168`); head is the last chunk-0
  file. Float matrix build (mul.s/add.s/sub.s/neg.s → stack matrix), ends
  `jr $ra` `0x11160`.
- `0x11168..0x1237C` — **unit/character-record subsystem**. Globals:
  `0x800B1804` = record count, `0x800B180C` = record array base (stride `0x13C`),
  `0x800B1808/1810/1814/1818` related tables; `0x800B1828..183C` active-record
  pointers; `0x800B9890/9891/9894` = mode byte / counter / callback ptr;
  config block `0x800C4B60..`. Includes an indirect dispatch loop (`0x112E8`) and
  a tagged-byte script/command interpreter over unit records (`0x11920`, vtable
  `0x800B98B0`).
- `0x1237C..0x15098` — tiny accessor leaves (getters/setters of `0x800B18xx`),
  a 6-function cluster at `0x130B8`, a math cluster at `0x1353C` (incl.
  `sin_cos_approx` `0x13778`), an **opcode-handler table** (~40 handlers, jump
  table `0x800B98B0`) at `0x14338`/`0x145A8`, an allocator (`0x12530`), a command
  parser (`0x1299C`), and an LCG random (`0x13AA4`). Mostly `func_*` (identities
  unproven).
- `0x15098..0x1796C` — `memset`, `memmove`, plus dual-entry helpers and jump
  tables (targets in RAM `0x800BE6xx`, out of chunk).
- `0x1796C..0x19454` — **free-list pop/push** (`0x18DA8`/`0x18DD4`, jal target
  `0x800889A8`, 8 callers), float-conversion leaves, accessor leaves returning
  `&0x800F8B14`/`&0x800F8B4C`.
- `0x19454..0x1A734` — `set_byte_800f918d`/`get_byte_800f918c`; an `osTvType`
  (`0x80000300`) read dual-entry at `0x19FE4`.
- `0x1A734..0x1B0A0` — `encode_ascii_to_glyph`/`decode_glyph_to_ascii` (explicit
  A–Z/a–z/0–9 range maps; glyph table `0x800AA050+`).
- `0x1B0A0..0x1CA94` — **libultra/OS**: `cpu_set_int_mask` (mfc0/mtc0 `$12` +
  MI_INTR_MASK), `ai_get_len`/`ai_get_status`/`ai_set_next_buffer` (AI audio
  registers); jump table `0x800BE690`.
- `0x1CA94..0x1FFEC` — float/math (`float_ldexp_d`) + libc; jump tables
  `0x800AE6C8/E700/E7F8/E820` and float pools live in RAM beyond the chunk.
- `0x1FFEC..0x21000` — free-list pop/push over `0x800AA710`, node-free /
  float-scale / list-min-search leaves, `list_insert_head`, `list_unlink`,
  `bump_alloc`, `mem_byte_copy`, libultra cache ops (`os_inval_dcache`,
  `os_inval_icache`, `os_writeback_dcache`, `os_writeback_dcache_all`),
  `os_virtual_to_physical`, `sqrtf` (`sqrt.s` leaf), and a trig kernel (`0x20BF0`).

## Identified-but-unnamed subsystems (future naming upgrades)

Strong structural identities the swarm refused to name without symbol proof — good
targets for a later pass: the unit-record dispatcher/script-interpreter cluster
(`0x11920`, vtable `0x800B98B0`); the ~40-entry opcode-handler table
(`0x14338`/`0x145A8`); an allocator (`0x12530`) and a command parser (`0x1299C`);
the LCG random (`0x13AA4`, seed `0x12345678 → 0x800B1824`); free-list push/pop
pairs (`0x18DA8`/`0x18DD4`, `0x2019C`/`0x201C8`); ~100 tiny global getter/setter
accessors over `0x800B18xx`/`0x800C4Bxx`/`0x800F8Bxx`.

## Boundary corrections (verified from disasm)

- **Un-merges (parent hid functions in trailing bytes):** e.g. `0x12400..0x12444`
  is **seven** distinct tiny `jr $ra` getter/setter leaves, not trailing words of
  `func_0001237C`; the `0x130B8` record was 6 functions; `0x1353C` was 4; the
  `0x14338`/`0x145A8` "partition" was ~40 individual jump-table handlers; `0x18C40`
  was 3; `0x18E4C` was 3; `0x19050` was 3; `0x1989C` was 3; `0x1FFEC` was 3;
  `0x20234` was 5; `0x20BE0` (sqrtf) split from the following trig kernel.
- **Preamble-orphans folded forward** (read-before-write global load precedes the
  parent prologue): `0x17990`, `0x18380`, `0x183C4`, `0x15D08`, `0x1A87C`,
  `0x1FBA0`, `0x1FBCC`, `0x20870`, and the `0x11168` leading pad onto
  `func_00011168`.
- **Genuine dual-entries kept as one file (secondary in `secondaryLabels`):**
  `0x1237C/12384`, `0x12448/1244C`, `0x124AC/124B0`, `0x12614/12628`,
  `0x126AC/126BC`, `0x14530/145A8`, `0x14D70/14D78`, `0x14DD8/14DE0`,
  `0x15048/15050`, `0x151E0`, `0x15734`, `0x18568`, `0x189D0`, `0x18C40`,
  `0x18DEC`, `0x18F80`, `0x19FE4`, `0x1C040`, `0x1C6C4`, `0x20878`.
- **No standalone data/jumptable files inside the chunk:** every jump table
  (`0x800B98B0`, `0x800BE690`, `0x800AE6C8/E700/E7F8/E820`) and float/coefficient
  pool (`0x800BE4xx`) referenced here lives in RAM data **beyond** `0x21000`, not
  embedded in the code chunk. Flag those for data-vs-code handling when the
  full-ROM coverage track reaches them.

## Caveats / next frontier

- Medium-confidence names are hypotheses; confirm with runtime/symbol evidence
  before relying on semantics. `func_*` names are pure address labels.
- Next split frontier: **`0x00021000` (chunk 2)**. Promote with the now-fixed
  `tools/promote_original_mips.js` (it merges; seeds a splittable single part),
  then `tools/dump_function_context.js --start 0x21000 --end <next>` and the same
  9-slice swarm pattern. Expect the same parent-DB defects (hidden tiny leaves,
  preamble-orphans, dual-entries) — validate every boundary from disasm.
