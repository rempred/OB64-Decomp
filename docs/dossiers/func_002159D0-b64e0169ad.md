## PURE_C branch reconstruction

The earlier exact-length candidate differed at the established allocator-owner
scheduler tie and at the type-`0x41` branch pair. Compiler-pass probes showed
that KMC's late-jump output had the retail `bne`/unconditional-jump CFG, but the
delay-slot relaxation pass inverted and exchanged those targets because it
predicts an inequality branch as likely taken.

A bounded pure-C source shape resolves that branch without emitting extra
instructions. The type byte is copied through a byte-width local before an
infinite loop whose two paths both leave the loop. This preserves the retail
branch orientation while retaining the retail `$a0`/`$a1` allocation. The
resulting PURE_C object has the exact accepted extent, frame, CFG, opcodes,
registers, and complete 79-record relocation shape. After relocation masking,
only offsets `0x34`, `0x38`, and `0x3C` differ.

Representative alternatives that did not solve both branch orientation and
allocation included direct equality and inequality forms, empty-arm and boolean
switch forms, a `while` form, duplicated tail behavior, a full sparse switch,
signed and unsigned type locals, a structured outer loop, and an infinite loop
using the original full-width type local. The last form corrected the branch but
exchanged `$a0` and `$a1`; the byte-width copy is the minimal source distinction
that corrects both.

## Bounded compiler-influence fallback

The remaining three words are the same post-allocation scheduling tie documented
for `func_002158E4` and `func_00217BA8`: KMC normally saves the allocator return
before loading `D_801CE8BC`, while retail loads the owner first. The active
source uses one extended-assembly statement with an empty template. It ties the
allocator value to the long-lived snapshot output and presents the owner as a
simultaneous input. It emits no instruction and implements no behavior; its only
effect is to select the retail schedule.

This remains an assembler mechanism under source policy, so the translation unit
is truthfully `HYBRID_C`. A future PURE_C reopen requires a source shape or
compiler capability that represents the same dependency without an assembler
escape hatch.
