## Continuation result

The Wave 4 continuation corrected the earlier two-instruction length deficit and
most of the substantive code-shape differences. In particular, it recovered
the retail branch-likely type dispatch, the pointer-add operand order at
`0x1F4`, the load/compare/add register reuse at `0x23C..0x250`, both marker
paths at `0x254..0x2AC`, and the relocation-bearing `D_800EB1F0` address form.

After an instruction-by-instruction disassembly audit, the remaining machine
shape deviations are confined to five positions:

- `0x34`, `0x38`, and `0x3C`: KMC saves the allocator return in `$s0` before
  loading `D_801CE8BC`; retail loads the owner first and then saves `$v0`.
- `0x178` and `0x180`: KMC selects the inverse but semantically equivalent
  conditional/unconditional jump pairing for the `0x41` case.

The first cluster is identical to the three-word scheduler tie exhaustively
probed for `func_002158E4`; see
`docs/dossiers/func_002158E4-a493a3ded3.md`. That target required an empty
extended-assembly compiler influence to become exact and is consequently
`HYBRID_C`. Wave 4 forbids a hybrid body fallback for this large target, so
`func_002159D0` cannot be promoted as matching C with the available source
mechanisms even if the second cluster is resolved.

Tested continuation families included signed and unsigned scan values,
structured and goto-shaped dispatches, a switch lowering, reordered constants,
scoped pointer temporaries, duplicated edge computations, shared and separate
marker pointers, symbolic versus integer address construction, and allocator
result/argument evaluation-order variants. The preserved source is the strongest
exact-length PURE_C candidate; the active linker configuration remains unchanged
and the original assembly remains the sole owner.
