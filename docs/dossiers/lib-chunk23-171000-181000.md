## Parent-DB correction (the headline finding)
The parent functions DB lists ~35 "functions" spanning `[0x171EA0,0x181000]`, implying the whole
range is code. **It is wrong.** Two large gaps are non-executable DATA islands:
`0x175F28..0x177ED0` (8,104 B) and `0x17BCD0..0x17F9C0` (15,600 B). Both were proven to contain
**0 `addiu $sp,-N` prologues and 0 `jr $ra` (0x03E00008)** by an independent byte-exact scan AND
by two adversarial data-island verifiers each scanning every word. The parent's
`func_00177D20` is a `0x80218D00` pointer run inside island 1's pointer table (a false positive,
correctly absorbed into `table_00177B44`). Every code/data boundary here is pinned from
byte-exact returns/prologues, never the DB.
