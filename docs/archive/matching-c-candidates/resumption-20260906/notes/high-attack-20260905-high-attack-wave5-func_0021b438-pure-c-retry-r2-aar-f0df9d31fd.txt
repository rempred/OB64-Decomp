## Why B894's successful reuse does not transfer

B894 E6 reused `temp_s0_30`. That scalar carries an early dispatch byte in retail `$s0`, dies,
and is later reset as a five-record loop index that retail also places in `$s0`. The two roles are
nonoverlapping, and the target already demonstrates the shared hard-register identity. Reusing one
C scalar therefore supplied the compiler with the exact affinity that retail exhibits.

B438's remaining inner cycle is different:

- strongest adjustment is live in retail `$s4` from its initialization through the final actor
  convergence;
- other slot is live in `$s3` for the three-entry actor scan; and
- other cursor is live in `$s2` across that same scan.

These values overlap. The E41 probe measures the accumulator at 43 weighted references / 131
instructions, cursor at 19 / 82, and slot at 19 / 83. GCC therefore allocates the accumulator
first and emits candidate `$s2/$s3/$s4`; retail needs `$s4/$s2/$s3`. There is no earlier or later
independent `$s2`, `$s3`, or `$s4` target role to reuse. Every semantically available B438 scalar
either overlaps the trio or belongs to a caller-register/stack role whose reuse would add a
target-visible saved-register operation.

The outer cycle also has no disjoint reuse surface. Owner classification, other classification,
and the outer cursor overlap. E41's reversible owner-value pair puts the cursor in exact `$fp` but
overshoots the desired priority interval, yielding owner `$s6` and other `$s7` instead of retail
owner `$s7` and other `$s6`.

## Assessment of the remaining B894 changes

B894's other successful changes solve mismatch families absent from E41:

1. Duplicating a counter initialization inside branch arms ended an accidental lifetime across a
   call. B438's disputed values intentionally survive nested calls.
2. A persistent volatile pointer fixed repeated global byte read/modify/write base materialization.
   B438 contains no equivalent family, and its exact stack arrangement depends on the current
   nonvolatile owner plus split cursor update.
3. Moving two initializations fixed delay-slot and address-materialization scheduling. E41 already
   matches every opcode, delay slot, stack offset, width, and branch polarity.
4. A genuine `for`/`continue` loop preserved B894's branch-likely and duplicate increments. B438
   previously tested indexed and explicit bottom-tested versions of the corresponding inner loop;
   GCC emitted the same object, and E41's CFG is already exact.
5. An in-place address update fixed a commutative operand register. B438's remaining executable
   differences are coherent saved-register cycles rather than an address-expression edge.

This comparison falsified the leading interpretation that B894 supplied one untested B438
lifetime/control-flow transformation.

## Why no source experiment was run

The assignment allowed a bounded retry only if the neighboring exact source yielded a concrete,
untested hypothesis. Compiling a reuse of `owner_value`, `other_value`, `other_index`, `other_slot`,

the measured interference graph or create a retail-visible operation. Repeating loop spellings,
copy boundaries, initialization ordering, or volatile-pointer methods would duplicate revision-1
experiments without new evidence.

The correct fail-closed action was therefore to stop before source mutation. No diagnostics root
was created and no candidate ID or run belongs to revision 2.
